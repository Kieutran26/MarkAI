Fork = copy toàn bộ repo sang GitHub account của bạn. Bản gốc không bị động vào. Bạn có toàn quyền sửa trong bản sao của mình.

02

Fork khác Clone thế nào

Fork
GitHub (người khác)
GitHub (của bạn)
Clone
GitHub
Máy tính của bạn
Fork: vẫn trên GitHub, người khác thấy được, có thể tạo PR
Clone: tải về máy, làm việc offline, không ai thấy
Vibecode thường: Fork trước → Clone bản fork về máy

Fork = server → server. Clone = server → máy bạn. Khi làm việc với team, fork trước rồi mới clone. Đừng nhầm hai khái niệm này khi nói với dev.

Fork → Edit → PR → Merge = chuẩn quy trình đóng góp. Bạn không sửa thẳng repo người khác — đề xuất qua PR để họ duyệt.

04

Phân kỳ

main
fork
Cùng điểm bắt đầu → đi hai hướng khác nhau

Sau khi fork, repo gốc tiếp tục cập nhật mà fork của bạn không tự nhận. Cần sync (pull từ gốc vào fork) để tránh bị tụt hậu — hay gặp khi báo "merge conflict".

Fork = copy repo của người khác sang GitHub account của bạn, không chạm bản gốc. Ba điều marketer cần nhớ: (1) Fork khác Clone — fork vẫn trên server để team thấy, (2) Luồng chuẩn là Fork → Sửa → Pull Request → Merge — không bao giờ sửa thẳng repo người khác, (3) Fork có thể phân kỳ — gốc cập nhật mà fork không tự sync, cần bảo dev pull upstream. Khi nói "fork repo đó đi" = copy về account mình để tự do thử nghiệm.
