Push = từ máy lên server. Pull = từ server về máy. Hai hướng ngược nhau. Pull cập nhật code mới nhất từ team về local của bạn.

02

Pull = Fetch + Merge

Fetch
GitHub
Bộ nhớ tạm
Tải code mới về nhưng chưa ghép vào file
Merge
Bộ nhớ tạm
File của bạn
Ghép code mới vào file đang làm việc
Hai bước liền — không phải chỉ "download"

Pull không phải download đơn giản. Nó fetch (tải về bộ nhớ tạm) rồi merge (ghép vào file). Nếu ghép lỗi → conflict.

03

Pull luôn là bước đầu tiên trong ngày. Bỏ qua → code bạn cũ hơn bản gốc → push bị reject hoặc tạo conflict.

04

Khi pull gặp conflict

bạn
.hero { color: #fff; }
team
.hero { color: #000; }
<<<<<<< HEAD
bạn
color: #fff;
=======
team
color: #000;
>>>>>>>> main
MERGE CONFLICT — cần xử lý tay

Cả bạn và team đều sửa cùng dòng → Git không biết giữ cái nào. Nó chèn marker vào file — bạn phải chọn giữ hoặc gộp tay, rồi commit lại.

Pull = tải thay đổi từ GitHub về máy và ghép vào code đang làm (fetch + merge). Ba điều marketer cần nhớ: (1) Pull ngược hướng Push — từ server về local, (2) Luôn pull trước khi code — nếu không, code bạn sẽ lỗi thời so với team, (3) Conflict xảy ra khi cùng sửa một chỗ — Git không tự quyết, bạn (hoặc dev) phải chọn giữ cái nào. Khi báo lỗi "pull bị conflict" = team sửa trùng phần bạn sửa, không phải "máy bị hỏng".
