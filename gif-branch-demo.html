01

Branch là sao

Branch = đường song song tách từ main. Code trên branch không ảnh hưởng main. Khi xong → merge lại. Như bản nháp song song với bản chính.

02

Tại sao cần branch

Sửa trực tiếp trên main → rủi ro cho cả team
main
index.html
→
index.html
!
Sửa trên branch → an toàn, merge khi sẵn sàng
branch
index.html
→
index.html
✓

Sửa thẳng main = cả team thấy code bị hỏng ngay. Sửa trên branch = chỉ bạn thấy, thử xong rồi mới merge. Branch = vùng an toàn để thử sai.

03

Vòng đời branch

Tạo
Chuyển
Code
PR
Merge
Tạo branch mới từ main
Chuyển workspace sang branch đó
Sửa code, commit trên branch
Gửi Pull Request đề xuất
Ghép vào main, có thể xóa branch

5 bước: Tạo → Chuyển → Code → PR → Merge. Sau merge, branch thường bị xóa vì đã hoàn thành nhiệm vụ. Không giữ branch rác.

04

Các loại branch

main
Production — code đang chạy thật trên server, luôn ổn định
develop
Staging — nơi gộp feature trước khi lên main, test trước
feature/*
Working — tính năng mới, fix bug, thử nghiệm, ngắn hạn

main = production, không sửa trực tiếp. develop = vùng tập trung trước khi lên main. feature/* = từng tính năng nhỏ, xong rồi xóa. Ba tầng, ba mục đích.

Branch = đường song song tách từ main, cho phép sửa code mà không ảnh hưởng bản gốc. Ba điều marketer cần nhớ: (1) Không bao giờ sửa thẳng main — luôn tạo branch trước, (2) Branch có vòng đời: Tạo → Chuyển → Code → PR → Merge → Xóa, (3) main = production luôn ổn định, feature/* = thử nghiệm xong rồi gộp. Khi nói "tạo branch đi" = tạo bản sao song song để tự do sửa, không sợ phá hỏng code đang chạy.
