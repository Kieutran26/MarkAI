Đọc hiểu
File text đơn giản. Mỗi dòng 1 cặp:

TÊN_BIẾN=giá_trị

Dấu # đầu dòng = comment, code bỏ qua.

Chứa mật khẩu, API key, đường dẫn database — những thứ không được viết thẳng vào code.
.env file
Code đọc biến
Kết quả
.env = file ẩn chứa "bí mật" của project. Thay vì ghi thẳng mật khẩu vào code, code đọc từ file .env. Giống bạn lưu password trong trình quản lý mật khẩu thay vì dán vào mỗi trang web.

dbHost → DB_HOST Chữ hoa, gạch dưới

.env bắt buộc viết CHỮ_HOA + GẠCH_DƯỚI. Sai quy tắc → code không đọc được biến. Khi dev báo "env variable not found" → kiểm tra xem tên biến trong .env có khớp chính xác chữ hoa/thường không.

Cùng tên biến, khác giá trị → cùng code chạy khác nhau. DB_HOST=localhost trên máy dev, DB_HOST=prod.db.com trên server thật. Code không cần sửa — chỉ cần load file .env đúng.

Tại sao không push .env lên Git

An toàn: .env trong .gitignore
# .gitignore
.env
.env.local
.env.production
Git bỏ qua file .env → không bao giờ lên GitHub. Mật khẩu chỉ tồn tại trên máy dev và server.
Git log: KHÔNG chứa .env
Rò rỉ: .env bị push
DB_PASS=
STRIPE_KEY=sk_live_abc123...
Ai cũng xem được trên GitHub. Bot scanner tự động tìm key → báo cho chủ sở hữu hoặc attacker.
GitHub: công khai, searchable
Push .env lên GitHub = dán mật khẩu lên bảng công cộng. Có bot tự động scan GitHub tìm API key bị lộ. Khi dev xin bạn "thêm .env vào .gitignore" → họ đang bảo vệ mật khẩu project. marketer không cần hiểu chi tiết, chỉ cần không bao giờ gửi file .env.

Thực hành

Mục tiêu: Điền giá trị cho các biến .env → thấy ngay output thay đổi. Thử nhập sai tên biến để thấy lỗi.
.env
DB_HOST=
DB_USER=
STRIPE_KEY=
DEBUG=
true
Quick:
node server.js
Click "Sai tên biến" → hệ thống tự đổi "DB_HOST" thành "db_host" (chữ thường). Terminal sẽ báo lỗi ngay. Đó chính xác là lỗi marketer hay mắc khi sửa .env.
