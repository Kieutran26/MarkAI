.gitignore hoạt động như bộ lọc ở cổng. File khớp pattern → bị chặn không commit. File không khớp → đi qua bình thường.

02

Cái gì thường ignore

.gitignore
.env # API key, mật khẩu
node_modules/ # thư viện cài
.DS_Store # file hệ thống Mac
dist/ # bản build
*.log # file log
.env chứa secret — lộ = bị hack
node_modules có hàng nghìn file — commit = repo nặng chậm
.DS_Store chỉ có trên Mac — người khác không cần
dist/ là file tạo ra — có thể build lại bất cứ lúc nào
*.log — file tạm, không phải source code

Ba lý do chính để ignore: bảo mật (.env), repo nhẹ (node_modules), không phải source (dist/, log).

03

Trước / Sau khi có gitignore

Không có .gitignore
index.html
style.css
.env
API_KEY=sk-xxx...
node_modules/
Secret lộ trên GitHub!
Có .gitignore
index.html
style.css
Chỉ code thật — sạch & an toàn

Không có gitignore = toàn bộ đẩy lên GitHub, kể cả API key. Có gitignore = chỉ source code đi lên. Một file .env lộ có thể khiến toàn bộ hệ thống bị compromised.

04

Cách viết pattern

.env
chính xác file .env
*.log
mọi file đuôi .log
dist/
cả thư mục dist
Tên chính xác — chỉ block file tên ".env"
Dấu * = wildcard — error.log, debug.log, bất kỳ .log nào
Dấu / cuối = cả folder — mọi file bên trong dist đều bị ignore

Ba pattern cơ bản: tên chính xác (.env), wildcard * (*.log = bất kỳ file .log), thư mục / (dist/ = toàn bộ folder). Biết ba cái này là đủ để đọc và sửa gitignore.

.gitignore = file text nằm trong project, chứa danh sách pattern. Git đọc file này trước khi commit — file khớp pattern sẽ bị bỏ qua. Ba điều marketer cần nhớ: (1) .env BẮT BUỘC phải ignore — chứa API key, mật khẩu, lộ lên GitHub là thảm họa, (2) node_modules/ và dist/ nên ignore — không phải source code, commit vào chỉ làm repo nặng, (3) Pattern cơ bản: tên chính xác (.env), wildcard (*.log), thư mục (dist/). Khi dev nói "thêm vào gitignore" = ghi pattern vào file .gitignore để Git không commit file đó.
