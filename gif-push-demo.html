Push = từ máy lên server. Code trên MacBook của bạn được tải lên GitHub. Ai có quyền truy cập repo đều thấy thay đổi ngay sau push.

02

Commit trước, Push sau

Working

Sửa file → file nằm trong Working Commit → file lưu vào Local (vẫn trên máy) Push → file mới lên GitHub (ai cũng thấy)

Commit ≠ Push. Commit lưu snapshot trên máy. Push gửi snapshot đó lên server. Báo "đã commit" không nghĩa là dev đã thấy — phải push mới lên GitHub.

Push bị reject khi remote có commit mới mà local chưa có. Giải pháp: pull trước → push sau. Đây là lỗi "push rejected" phổ biến nhất khi làm việc nhóm.

Push nằm giữa commit và live. Không push = code chỉ trên máy bạn. Push xong = CI/CD tự deploy, hoặc dev pull để tiếp tục làm.

Push = tải commit từ máy lên GitHub. Ba điều marketer cần nhớ: (1) Push khác Commit — commit lưu local, push gửi lên server, (2) Push có thể bị reject khi người khác đã push trước — cần pull trước rồi push lại, (3) "Đã commit rồi mà sao chưa thấy" = chưa push. Khi báo lỗi, nói rõ "push bị rejected" thay vì "lên GitHub không được" — dev sẽ biết ngay vấn đề.
